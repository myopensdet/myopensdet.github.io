# Testing through the sprint

## Refinement (before the sprint)

- [ ] `python story_check.py` on each story; questions asked and answered
- [ ] Each criterion has a real example with values
- [ ] Test data and environments needed are known
- [ ] Testing effort is part of the estimate, not added later

## Planning (day 1)

- [ ] Stories small enough to test within the sprint
- [ ] Testing work is visible on the board (tasks or a column)
- [ ] Which stories need the most testing, and who tests them

## During the sprint

- [ ] Tests written while the code is written (from the criteria), not after
- [ ] Testing starts as soon as the first part works, not on the last day
- [ ] Bugs talked about with the developer the same day
- [ ] Nightly run read every morning

## Review (end of the sprint)

- [ ] Only stories that meet the Definition of Done are shown as done
- [ ] Known bugs and risks said out loud

## Retrospective

- [ ] One testing problem from this sprint, and one change to try next sprint
- [ ] Bugs that escaped: where could we have found them earlier?
